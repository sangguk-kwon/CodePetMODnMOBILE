# 실시간 작업 진행 보고 (Progress Updates) 구현 계획

기준일: 2026-11-11 (Asia/Seoul) · 상태: **Phase 1 구현·미배포 / Phase 2 후속**

## 목표와 일정

긴 작업 중 사용자가 확인된 작업과 현재 상태를 에이전트별로 볼 수 있게 한다.
Claude Code와 Codex에 같은 진행 이력 UI와 상태 규칙을 제공하는 것을 Phase 1의 필수 완료 기준으로 삼는다.
화면의 일관성을 위해 각 CLI가 제공하지 않는 이벤트나 완료 사실을 만들어내지는 않는다.

P2의 이벤트 계약과 P3의 작업 표시 요구에 연결한다. 2026-11-11 사용자 추가 지시로
대화별 허용 메뉴와 Phase 1을 같은 작업으로 구현했다. 기존 #18/#19 병합을 확인하고
`origin/develop`의 `3140079`에서 분기했다. 브라우저 연결보다 먼저 착수한 것은 이번 사용자
지시에 따른 변경이며 다른 단계의 선행 조건과 Phase 2의 우선순위는 바꾸지 않는다.
Phase 2는 CLI별 공개 중간 메시지 지원과 비용 검토를 마친 뒤 진행한다.
Phase 1은 앱 코드에서 구조화 이벤트를 요약하며 프롬프트·말투·성격을 바꾸지 않는다.

## 구현한 범위와 제한 (2026-11-11)

- `chat-progress.js`는 허용한 lifecycle 필드만 고른다. 명령 인자·경로·출력·비공개 추론·임의 도구 이름을 새 진행 이력에 넣지 않는다. Claude/Grok tool_use/tool_result, Codex exec/App Server의 명령·파일·MCP·웹·추론 시작 메타데이터, AGY의 확인 가능한 step 상태를 처리한다. Gemini는 새로 추가하지 않는다.
- 도구 ID를 해시로 연결해 stream/assistant 중복을 제거한다. ID 없는 같은 종류/상태는 500ms 안에 개수로 묶고 성공 결과를 임의 대응하지 않는다. 명확한 테스트 명령만 분류하고 실제 종료 코드를 표시한다. 도구별 성공 근거가 없으면 전체 응답이 끝나도 결과 미확인으로 남긴다.
- 기존 run IPC를 재사용한다. 진행 스냅샷은 150ms로 묶고 실행 종료·취소·실패는 즉시 보낸다. 실행당 최근 80행, 대화당 최근 40실행, 메모리 캐시 최대 64대화다. JSON 파일 읽기 상한은 2MiB이며 넘거나 손상되면 선택 이력을 복원하지 않는다. 과거 행 생략은 화면에 표시한다.
- `progress.json`에 허용한 요약만 저장한다. 새로고침·대화 전환 후 복원하고 앱 중단으로 실행 상태를 확인할 수 없으면 결과 미확인으로 복원한다. 실행 ID는 재시작 사이 충돌하지 않게 바꿨다. 선택 이력 저장 실패로 기존 작업을 실패시키지는 않는다.
- 채팅 메시지 안의 같은 진행 UI를 Claude/Codex에 제공한다. 완료 후 접기/펼치기, 취소 이력 보존, 마지막 확인 시각/경과시간, 병렬 실행 구분을 지원한다. 상태줄의 원문 명령/도구 이름도 일반 분류로 대체한다.
- 추가 모델 호출·프롬프트 삽입이 없다. AI가 문장으로 작성하는 자연어 중간 보고는 Phase 2로 남긴다.
- 전체 테스트·실제 Electron renderer/preload/IPC와 모의 실행기, 설치된 Claude/Codex CLI + 로컬 모의 공급자로 검증했다. 실제 구독 공급자·장시간 사용자 작업·다양한 CLI 버전은 미검증이며 CLI가 내보내지 않은 결과를 보완하지 않는다. 세부 근거는 STATUS를 따른다.

## 2. Phase 1 — 이벤트 기반 진행 현황

**예상 난이도: 중하.** 기존 이벤트→IPC→렌더러 경로를 재사용한다. 다만 종료 처리·보안·병렬 이벤트 정합성은 별도 검증이 필요하다.

- [ ] 파일 조회·검색·편집, 명령/도구 시작·결과·실패, 확인 가능한 추론 시작 메타데이터를 공통 진행 이벤트로 변환한다.
- [ ] 도구 이름·분류·ID·결과 상태·종료 코드처럼 검증 가능한 필드만 사용한다. 추론 본문·명령 출력·민감한 파일 내용은 표시하지 않는다.
- [ ] 테스트 실행을 식별할 근거가 있으면 시작/종료/실패를 표시한다. 임의의 명령에 `test`가 들어간다는 이유로 테스트라고 판정하지 않는다. 근거가 없으면 일반 명령 실행으로 표시한다.
- [ ] 성공 결과가 없는 도구는 완료로 표시하지 않는다. 시작 이벤트만 있으면 진행 중/결과 미확인으로 남기고, 전체 run 종료가 도구별 성공을 대신하지 않게 한다.
- [ ] 추가 LLM 호출·요약 호출·진행 보고용 프롬프트 삽입 없이 로컬 규칙으로 처리한다. Phase 1 자체의 추가 모델 토큰 사용은 0이어야 한다.
- [ ] 동일 ID의 stream 시작과 완성된 tool_use 메시지를 하나로 묶는다. 같은 상태 반복은 개수/시간 범위로 요약하되, 서로 다른 도구와 실패/취소/완료 전환을 지우지 않는다.
- [ ] 갱신 묶음 간격과 최대 이력 수·IPC payload 크기·DOM 노드 수를 정하고 측정한다. 최종 상태는 묶음 대기 없이 반영하며 생략/요약 사실을 표시한다.

문구와 근거의 관계:

| 확인된 근거 | 표시 예 | 표시하면 안 되는 결론 |
|---|---|---|
| Read/Search 도구 시작 | 관련 파일 조회 중 / 파일 검색 중 | 프로젝트 구조 확인 완료 |
| 해당 도구의 성공 결과 | 파일 조회 완료 / 검색 완료 | 수정 대상 분석 완료 |
| Edit 도구 시작·성공 결과 | 파일 수정 중 → 파일 수정 완료 | 코드가 올바름 / 모든 수정 완료 |
| 식별 가능한 테스트 명령 시작·종료 코드 | 테스트 실행 중 → 테스트 명령 종료(코드 0 또는 실패 코드) | 로그에 없는 전체 테스트 통과 / 제품 검증 완료 |
| run 성공 종료 | 작업 응답 완료 | 모든 테스트·검증 완료 |
| 새 이벤트 없이 시간이 흐름 | 마지막 확인: 파일 조회 완료 · 이후 경과시간 | 다음 단계 추측 / 가짜 완료율 |

명시적인 단계/계획 이벤트가 제공되면 그 단계 상태를 근거와 함께 표시한다.
자연어로 에이전트가 말한 완료와 도구 결과로 확인한 완료는 출처를 구분한다.

## 3. Phase 2 — 공개 자연어 중간 보고

**예상 난이도: 중상.** 공급자별 메시지 종류·스트림 경계·최종 답변 판정과 비용 확인이 선행돼야 한다.

- [ ] CLI가 실제 제공하는 사용자용 commentary/중간 assistant 메시지·텍스트 스트림의 구분 방법을 버전별로 확인한다.
- [ ] Claude와 Codex 모두에서 공개 중간 메시지를 동일 UI로 표시하는 경로를 검증한다. 중간 메시지 구분이 불가능한 CLI에는 Phase 1과 기존 본문 스트리밍을 유지하고 제한을 표시한다.
- [ ] 내부 비공개 Chain-of-Thought, thinking/reasoning 본문, 암호화·서명된 추론 데이터는 수집·복호화·노출 대상에 넣지 않는다. 시작 상태 메타데이터와 공개 요약은 구분한다.
- [ ] CLI가 공개하는 중간 보고를 우선 사용한다. 미지원 CLI의 빈칸을 별도 모델 호출이나 추측 문장으로 채우지 않는다.
- [ ] 보고 텍스트는 에이전트의 설명으로 표시하고, “테스트 통과” 등의 주장을 도구 검증 결과로 자동 승격하지 않는다.
- [ ] 기존 final/partial 처리와 별도 중간 보고의 중복, final 누락, 대화 기록 오염을 방지한다. 승인 요청과 질문도 최종 답변으로 잘못 처리하지 않는다.
- [ ] 설정에서 자연어 중간 보고 표시를 켜고 끄는 방안을 검토한다. 표시만 숨기는 것은 이미 생성된 토큰을 절약하지 않음을 안내한다.
- [ ] 모델·CLI·옵션별 입력/출력 토큰, 지연, 표시 빈도, 중복 저장 영향을 측정한다. 네이티브 스트림에 보고가 없어서 프롬프트 보완이 필요하다면 별도 검토 후 선택 기능으로 다룬다.

실제 공급자 확인에는 가상 데이터와 짧은 표본을 사용하고, 모의 테스트 결과와 구분해 기록한다.
설치된 CLI가 이벤트를 제공하지 않으면 해당 항목을 미지원/미확인으로 표시한다.

## 5. 이벤트 처리 구조와 변경 대상

예정 흐름: **CLI JSONL/어댑터 → 기존 파서와 trace 정규화 → 진행 전용 안전 요약 → 기존 run IPC → 진행 이력 reducer → 채팅 UI**.
도구 기록 저장과 화면 요약은 분리하되 동일 호출 ID로 연결한다. 원문 trace를 renderer로 복사하지 않는다.

| 파일 | 검토·변경 범위 |
|---|---|
| `src/chat/chat-events.js` | CLI별 시작/종료/오류 이벤트 정규화. Phase 2 공개 중간/최종 메시지 구분 |
| `src/chat/chat-trace-events.js` | 도구 ID·결과·종료 코드 재사용, 민감한 입력/출력과 분리한 진행 요약 필드 |
| `src/chat/chat-agent-runner.js` | 진행 이벤트 전달, 실제 종료·취소·실패 상태의 일관성 |
| `src/chat/chat-room.js`, `src/chat/chat-ipc.js`, `src/chat-preload.js` | sessionId/agentId/runId와 순번 전달, stale 차단, 기존 스트리밍·승인 이벤트와 공존 |
| `src/chat.js`, `src/chat.css` (필요시 `src/chat.html`) | 에이전트/실행별 시간순 이력, 경과시간, 접기/펼치기와 접근성 |
| `src/chat/chat-traces.js`, `src/chat/chat-store.js` | 기존 저장/재생 가능성 검토. 완료 메시지 교체 후 이력을 보존하는 bounded 요약 저장·복구 방식을 결정 |
| `src/chat/chat-run-diagnostics.js` | 기존 비밀 값 필터 재사용 검토. 필터만 믿지 않고 화면용 필드를 허용 목록으로 구성 |
| `src/chat/chat-prompt.js` | Phase 1 변경 금지. Phase 2 네이티브 메시지로 해결되지 않을 때만 비용·말투·성능 영향을 별도 검토 |

진행 객체 후보: `sessionId`, `agentId`, `runId`, `eventId/sequence`, `toolCallId`(있을 때만),
`receivedAt`, `kind`, `state`, `safeLabel`, `count`, `source`.
실행 내 수신 순번으로 순서를 정하고 표시 시간은 수신 시각임을 구분한다.
취소·실패·완료 후 늦은 이벤트, 실행 재시도, ID 없는 공급자의 이벤트 매칭 정책을 명시한다.
이력 저장은 요약만 대상으로 보관 한도를 적용하며 기존 원본 대화·CLI 세션 저장 형식을 파괴하지 않는다.

## 6. UI 방향

- 기존 상태 표시줄을 유지하면서 해당 에이전트의 메시지 아래에 시간순 진행 이력을 둔다.
- 같은 세션에서도 참가자·계정·실행별로 분리한다. 동시 도구와 재시도도 하나의 성공 단계로 합치지 않는다.
- 완료된 이력은 접을 수 있고 다시 펼칠 수 있게 한다. final 메시지가 live 노드를 교체하거나 실패로 노드가 사라져도 요약 이력이 유실되지 않게 한다.
- 취소/실패/완료를 명시적으로 구분한다. 승인 대기는 “사용자 승인 대기”로 표시하며 추론·도구 성공으로 바꾸지 않는다.
- 이벤트가 없는 긴 작업은 마지막 확인 상태·해당 시각·이후 경과시간만 갱신한다. 무응답만으로 종료나 추론 중이라고 단정하지 않는다.
- 자동 스크롤은 사용자의 읽기 위치를 보존하고, 접기/펼치기의 키보드 조작과 스크린리더 알림 빈도를 검증한다.
- 진행 UI에는 비밀 값·인증 정보·명령 출력·파일 내용이 노출되지 않게 한다. 경로나 명령 인자가 민감할 때는 분류명으로 대체한다.

## 7. 테스트·검증과 주요 위험

- [ ] Claude/Codex 필수 fixture: 시작→성공, 시작→실패, 시작만 있음, 결과만 있음, 반복·알 수 없는 이벤트, 버전 차이.
- [ ] Grok/AGY fixture와 Gemini 미지원 처리. 누락된 종료 이벤트를 성공으로 보완하지 않는지 확인.
- [ ] 실행/계정/세션 격리, 병렬 도구, 지연·중복·역순 이벤트, 재시도, 취소·승인 대기·실패·완료 상태 확인.
- [ ] 테스트 명령의 확실한 근거와 종료 코드 보존. 일반 명령을 테스트로 오인하거나 응답 완료를 검증 완료로 표시하지 않는지 확인.
- [ ] 비밀 값·민감 파일 내용·공개 대상이 아닌 추론·악성 HTML·길고 빈번한 출력의 화면/IPC/요약 저장 누출 검사.
- [ ] Phase 1에서 모델 호출 수·프롬프트가 기존과 같고 추가 토큰 요청이 없음을 확인. 폭주 시 IPC·메모리·DOM 상한과 갱신 빈도 측정.
- [ ] 실제 Electron UI에서 이력 접기/펼치기, final 교체 후 보존, 경과시간, 읽기 위치, 재시작/기록 복원 정책 검증.
- [ ] 기존 본문 스트리밍, `[[CODEPET_TRACE:...]]` 제어 메시지 숨김, 세션 재개, 모델 변경, 호출 규칙, 에이전트 간 대화의 회귀 검사.
- [ ] Phase 2는 공개 중간 메시지와 final 분리·중복 방지·토큰/지연 영향을 모의 및 실제 CLI별로 따로 검증.

주요 위험은 **완료 근거 부족, 도구/실행 ID 누락과 중복, live/final 교체 시 이력 유실,
내부 추론·비밀 값 노출, 이벤트 폭주로 인한 UI 지연**이다. Phase 1의 범위를 단순 요약과
기존 전달 경로에 제한하고, Phase 2는 검증된 공개 메시지만 표시해 위험을 줄인다.

## 8. 완료 기준

Phase 1: Claude와 Codex에서 실제 확인된 이벤트의 시간순 이력을 같은 UI로 볼 수 있고,
추가 모델 호출/토큰 없이 중복·병렬·종료 상태를 정확하게 처리하며 기존 대화 기능이 유지된다.
실제 CLI가 제공하지 않는 항목과 실공급자 미검증 항목은 명시한다.

Phase 2: 각 CLI의 공개 중간 메시지 지원 범위와 비용을 기록하고, 지원 대상에서 최종 답변과
중복 없이 중간 보고를 표시한다. 비공개 추론은 노출하지 않으며 미지원 CLI의 보고를 생성하지 않는다.
